# PGN Tree Viewer (Rust / egui)

A desktop opening-tree viewer for an analysed PGN such as `../lemberger/variante.pgn`.
The bars, figurine move list and navigation buttons follow the ChessBase mobile app's opening view
(see `Screenshot_20261107_184229_ChessBase.jpg`), adapted for a PC screen: board and
continuation list are **side by side**.

Each continuation row shows (instead of games / score / year / Elo):

| column | meaning |
|---|---|
| move | `4.Qh5`, `4...exd4`, with the piece letter drawn as a figurine |
| count | number of continuations on the **next level** (children of that move only, not the whole subtree) |
| evaluation | evaluation of the position after the move, parsed from its comment (White's view) |

## Behaviour
- Starts **empty**. The user opens the PGN via the Open button or the ⋮ menu.
  No command-line argument, no remembered last file, no automatic file
  watching or reloading. "Reload" in the menu re-reads the file only when clicked.
- Plain board: flat light/dark squares (`LIGHT_SQ` / `DARK_SQ` in `main.rs`), no wood
  textures, no background frame. Yellow arrow for the last move.
- Dark title bar: ← (start position), title (`ChapterName` / `Event` header / file name),
  open-file icon, ⋮ menu (Open, Reload, Copy FEN, Flip).
- Right side: grey strip with the current line (start trimmed with "…") and the evaluation of the current position.
  Below it is the list of continuations; click a row to play it, or hover to see the full comment.
- Dark bottom bar: start, back, forward (selected move), end of line, flip.
- Keys: ←/→ back/forward, ↑/↓ select row, Enter = forward, Home/End, F = flip.
- eframe persistence stores only the flip state and window geometry.

## Android
- APK via `./build-android.sh` (no Gradle): `cargo ndk` builds the `cdylib`,
  `javac`+`d8` builds `android/java/.../MainActivity.java` (a NativeActivity subclass), `aapt2` links
  `android/AndroidManifest.xml` + `android/res`, then `zipalign` and `apksigner`. The output is `android/PgnTreeViewer.apk`, arm64-v8a only,
  minSdk 26, targetSdk 34 (34 on purpose: 35 would force edge-to-edge drawing under the status bar).
- Toolchain on this machine: `~/android/jdk17`, `~/android/sdk` (platform 34, build-tools 34.0.0,
  NDK 29), Rust target `aarch64-linux-android`, `cargo-ndk`. The signing key is `~/android/keys/pgntreeviewer.jks`
  (password in the script default). It must stay the same for app updates.
- File opening: `MainActivity.openPicker()` (ACTION_OPEN_DOCUMENT), plus "Open with" (VIEW) and Share (SEND)
  intents. Java reads the content:// URI and keeps {name, text, error}; Rust polls `take()` every 500 ms
  via JNI (`src/android.rs`, using `ndk-context`).
- System bars: the NativeActivity surface covers the whole screen (also under status/navigation bar).
  `MainActivity` records the window insets (OnApplyWindowInsetsListener). Rust polls `insets()` and keeps those
  areas free with dark panels. JNI/picker errors are shown in the status line instead of being ignored.
- Android-specific UI: no Reload, no Copy FEN. Portrait layout (board top, list below) is chosen whenever
  the window is taller than wide, also on desktop.
- No device or emulator is available here (no KVM access for the user), so the APK is only tested on a real phone.

## Files
- `src/app.rs`: UI, board, arrow, icons (shared). `src/main.rs`: desktop entry. `src/lib.rs`: lib + `android_main`
- `src/pgn.rs`: PGN → move tree (first game only, nested variations,
  `{}`/`;` comments, NAGs skipped, eval from `[%eval x]` or a leading `+0.35` / `#-3` token), unit tests
- `assets/pieces/*.png`: transparent pieces, generated by `tools/make_pieces.py`
  from `../lichesspuzzleviewer/assets/pieces` (light/dark difference matting)
- `dist/PgnTreeViewer-linux` (Linux/Ubuntu), `dist/PgnTreeViewer.exe` (Windows): release binaries
- `tools/build_tree.py`: generic version of `../lemberger/analyze.py`. It grows an analysed tree from
  a seed PGN with Stockfish; all rules are CLI options (`--time --multipv --branch --worse-cp --cutoff-cp --last-move`)
- `README.md`: user documentation, including the chapter on creating your own PGN (script and Claude prompt).
  Keep it in sync with UI or script changes. `docs/screenshot.png` is the README image.

## Running
`./dist/PgnTreeViewer-linux` or `PgnTreeViewer.exe`, then open the PGN.
Under WSLg the Wayland socket may be unusable. Run with `env -u WAYLAND_DISPLAY` to use X11.

Test aids (environment variables, used for screenshots only):
`PGNVIEWER_FILE=x.pgn` preloads a file, `PGNVIEWER_LINE="d4 d5 e4"` opens at that line,
`PGNVIEWER_PORTRAIT=1` opens a phone-shaped 420×900 window,
`PGNVIEWER_SCREENSHOT=out.png` saves a screenshot after a few frames and exits.

## Building / tests
```bash
./build.sh [windows|linux]     # into dist/ (Windows: static CRT, only system DLLs)
./clean.sh [target|dist]
cargo test --release --target x86_64-unknown-linux-gnu
```
`Cargo.toml` mirrors `../lichesspuzzleviewer`: eframe 0.35 with `default-features = false`
and the `wayland`/`x11` features required for the Linux build. Chess rules come from `shakmaty` 0.30.
